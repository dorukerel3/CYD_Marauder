# Building in the cloud (or any Linux box)

This repo is self-contained: `source/esp32_marauder` (sketch) + `source/libs` (all required
libraries, including the CYD-specific TFT_eSPI config and the patched BatteryInterface).

## Quick build

```bash
bash build.sh            # -> marauder_cyd_v2_0x0.bin  (flash at 0x0)
bash build.sh --release  # also creates a GitHub Release with the .bin (needs gh auth)
```

`build.sh` installs `arduino-cli` + ESP32 core 2.0.17 + `esptool`, compiles with the required
`-Wl,--allow-multiple-definition` linker flag, and merges a flashable 0x0 image.

## Flashing

- **USB:** `python -m esptool --chip esp32 -p <PORT> --baud 921600 write_flash 0x0 marauder_cyd_v2_0x0.bin`
- **Over Wi-Fi (no PC):** attach the built `.bin` to a **GitHub Release**, then on the device:
  Device → Update Firmware → **WiFi Update**. It joins a saved network (SD `/wifi_creds/<SSID>.txt`,
  file contents = password), downloads the latest release's `.bin`, flashes it, and reboots.

## Claude Code cloud notes

- Add a **setup script** that runs `bash build.sh` (or just the install steps) so the toolchain
  is ready. A ~300 MB core install can exceed the ~5 min setup-cache window — run the heavy
  download in the background if the cache won't build.
- Use a **Custom network allowlist** including: `github.com`, `raw.githubusercontent.com`,
  `objects.githubusercontent.com`, `espressif.github.io`, `downloads.arduino.cc`,
  `dl.espressif.com`, `pypi.org`, `files.pythonhosted.org`.
- The cloud sandbox has **no USB** — use the Wi-Fi OTA path above to flash.
- Tag pushes may be blocked in the sandbox; `build.sh --release` falls back to the REST API.

## NOT in this repo

- `sd folders/` — the offline OpenStreetMap tiles (several GB) live only on the SD card.
- Build artifacts and `*.bin` at the repo root (regenerated by `build.sh`).
